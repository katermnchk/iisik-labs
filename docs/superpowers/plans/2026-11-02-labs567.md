# План лабораторных работ 5–7

Цель: продолжить вариант 20 из ЛР4, сохранить GraphQL и бизнес-правила, заменить демонстрационные токены и локальные зависимости настоящей инфраструктурой.

Архитектура: отдельный Auth Service (учётные данные в auth_db, JWT, Redis-сессии), User Service владеет профилями и актуальными ролями. Gateway проверяет сессию через Auth, передаёт проверенный Principal по доверенному внутреннему gRPC. Все шесть сервисов используют свои PostgreSQL. Kafka доставляет события из транзакционного outbox в уведомления и аналитику. Redis кеширует направления с TTL; места и деньги не кешируются.

Решения: Java 17 и Spring Boot 3.5.7 сохранены. Дополнительный transport-модуль содержит общий protobuf-конверт, gRPC-клиент/сервер и наблюдаемость. Внешние HTTP-порты внутренних приложений привязаны к loopback; прежние demo endpoints закрыты. Внутренний gRPC защищён общим ключом окружения. Это локальный учебный стенд без публичного развёртывания.
