# Проверка безопасности ЛР5

Проверена текущая интегрированная версия после коммита `4c0c11c`.

## Исправленный обход внутренних HTTP маршрутов

Старый фильтр сравнивал raw URI с `/internal/`. Spring MVC удаляет matrix-параметры и декодирует сегменты, поэтому `/internal;x/v1/users/<id>` возвращал профиль без JWT с HTTP 200. Обычный `/internal/v1/...` возвращал 404.

`TransportConfig.internalHttpClosed` теперь использует путь внутри контекста приложения и `PathSegment.valueToMatch`, как маршрутизация Spring. Первый сегмент `internal` закрывается ответом 404. До исправления три теста обхода падали. После исправления проходят пять проверок: обычный путь, matrix-параметр, кодирование сегмента, context path и доступность health.

## Подтверждение

- Полный `./mvnw clean verify` на JDK 17: 84 теста, 0 failures/errors/skips.
- `python3 scripts/verify-lab5-security.py`: 79 успешных проверок GraphQL, Redis, PostgreSQL и внутренних HTTP путей.
- `docs/evidence/lab5-current/security.json`: ответы и результаты без JWT и паролей.
- 24 внутренних HTTP запроса: четыре формы пути для каждого из шести доменных сервисов. Все фактические ответы 404.

Проверены регистрация CLIENT, нормализация email, BCrypt и профиль в БД, ограничения пароля, запрет передать роль в RegisterInput, неверные учётные данные, повреждённая подпись, роль и владелец, смена роли и блокировка для старого JWT, независимые сессии, logout, несовпадение Redis userId с JWT subject, истечение сессии, отказ Redis и восстановление.

Для проверки TTL только новая тестовая сессия получает EXPIRE 1. JWT остаётся действующим. Redis кратковременно останавливается и запускается в finally; активная сессия сохраняется через AOF. Новый тестовый профиль возвращается в CLIENT/ACTIVE, созданные сценарием активные сессии отзываются.

TokenServiceTest содержит 14 проверок, включая девять неверных комбинаций claims и корректно подписанный запрещённый HS384. Текущие роли читаются из User Service на каждый GraphQL HTTP-запрос; claim role не является источником актуальных прав.

## Границы результата

Стенд локальный: loopback-порты, общий внутренний SERVICE_KEY и plaintext gRPC. TLS/mTLS, refresh tokens, ротация ключей и ограничение частоты входа не реализованы. Проверки не являются внешним пентестом или нагрузочным тестом. Формальные отчёты хранятся отдельно от репозитория. Не запускайте остановку Redis одновременно с ручной демонстрацией.
