# Проверка ЛР4

## Соответствие методичке

| Требование | Реализация | Проверка |
|---|---|---|
| Бизнес-Mutation | 9 полей SDL, MutationController, Commands | MutationTest, фактические HTTP-ответы |
| Query с фильтрацией | TourFilter и BookingFilter | GatewayTest, BusinessRulesTest, verify-lab4.py |
| Сортировка | Туров и броней, устойчивый порядок по id | JUnit и GraphQL HTTP |
| Агрегация | salesAnalytics, bookingSummary | Совпадение набора и суммы 270000 копеек |
| Создание и изменение | Тур, выезд, бронь, попытка оплаты, профиль | Реальные записи 4 БД |
| Условия и состояния | Версии, места, роли, даты, разрешённые переходы | 18 тестов business-core |
| Сервисный слой | business-core + Store/SeatPort | Resolver не содержит SQL/JPA/расчётов |
| Изоляция | Локальные заглушки, отдельные БД | Остановка 6 сервисов; запрет cross-DB |
| Подготовка к gRPC | Интерфейсы клиентов, DTO и порты | Реального gRPC и Kafka нет |

## Итог

76 JUnit, ошибок/пропусков нет. 50/50 интеграционных проверок. Повторяемый GraphQL smoke: 12/12. Запущены 7 JAR с PostgreSQL 16.4. Docker Compose не запускался: daemon отсутствовал. Полные результаты — docs/evidence/lab4, maven-verify.log и integration-summary.json.

## Дополнительные проверки

20 заявок на 7 свободных мест: 7 прошли, 13 получили INSUFFICIENT_SEATS, превышения вместимости нет. Проверены одновременно 20000 обновлений и 20000 чтений: существующий объект не пропадает.

Независимый обзор выявил недоступность DRAFT сотруднику и временное исчезновение memory-объекта между remove/add. Обе проблемы воспроизведены тестами и исправлены. Дополнительно причина и автор отмены передаются в историю, удержание ограничено началом выезда. Проверено восстановление local_tour_stub и квитанций после перезапуска.

## Границы этапа

Оплата только инициируется, callback и возвраты не реализованы. Автоматический таймер истечения и обновление аналитических проекций событиями не подключены. Состояния отдельных приложений независимы. Эти ограничения описаны в README и не выдаются за работающую межсервисную интеграцию.


После независимого ревью: строгие REST-контракты, AMOUNT_OVERFLOW, сравнение моментов времени через isEqual, положительные исходные сценарии 606/607, проверка V5 при обновлении существующего локального снимка, полный порядок 12 запросов Postman. Подробности — docs/review-lab4.md.
