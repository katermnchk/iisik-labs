# ЛР4: план реализации

Цель: расширить вариант 20 без сетевых межсервисных вызовов.

1. Добавить в contracts входные DTO и командные интерфейсы. Бизнес-правила вынести в business-core; хранилища задаются портами.
2. Реализовать сервисы туров, бронирований, платежей и пользователей. Проверить роли, версии, количество мест, сроки, повторные запросы.
3. Подключить те же сервисы к изменяемым заглушкам GraphQL и к PostgreSQL внутренних приложений через отдельные адаптеры. Resolver только делегирует.
4. Расширить SDL, добавить фильтры и сводку броней. Проверить успешные и ошибочные HTTP-сценарии, конкурентное бронирование.
5. Собрать проект, сохранить ответы и результаты тестов. Составить отчёт по оформлению ЛР3 и проверить все страницы.

Границы: без gRPC/Kafka и платёжного провайдера. Начало оплаты создаёт PENDING; подтверждение и возврат платежа относятся к следующему этапу. Заглушки хранят данные до перезапуска.
