# Ревью ЛР4 на текущем интегрированном проекте

Все девять бизнес-операций реализованы в сервисном слое, вызываемом GraphQL. Проверены входные значения, роли и владелец, оптимистические версии, снимок денег, идемпотентность, фильтрация/сортировка/агрегация, запись в собственные БД и допустимые состояния. По выбору автора для сдачи используется новая версия с реальными gRPC/Kafka, а не исторический mock-режим.

Исправлены два дефекта. Отмена ранее фиксировала квитанцию только после удалённого release, поэтому после сбоя тот же ключ мог отменить другую бронь и заблокировать исходный повтор. Теперь receipt связан с исходным payload в транзакции CANCELLING, replay продолжает отмену; финальная фиксация не вставляет receipt повторно. Второй дефект: nullable directions(activeOnly) принимался primitive boolean. Теперь Boolean нормализует null в true. Оба дефекта подтверждены падающими тестами до исправления; текущие 69 JUnit зелёные.

Реальный прогон: 63 проверки (46 основных GraphQL-запросов, проверки строк БД/инвариантов и одна временная фикстура). Остановка Tour проверяет постоянную связь ключа с исходной бронью и причиной. Повтор исходной команды восстанавливается. Для завершения поездки сначала отклоняется будущее начало, затем только у созданной этим тестом брони starts_at_snapshot переводится в прошлое SQL-фикстурой. Естественное течение времени не заявляется. Протоколы: docs/evidence/lab4-current.

Стенд: PostgreSQL16.15, Flyway включён, Redis7.2.4, Kafka3.7.0. Найден OOM Kafka при параллельно работающих стендах: проверочный стенд ЛР3 остановлен, Kafka heap ограничен128-256MiB. После восстановления реальный прогон успешен.

Изоляция означает отдельные БД и отсутствие прямых межсервисных SQL-запросов. Она не означает независимую доступность внешнего сценария. Банк не подключён, оплата учебная; межсервисной ACID-транзакции нет. Административное завершение не заменяет подтверждение оплаты. Укрупнённые advisory locks ограничивают throughput и не выдаются за промышленное масштабирование.
