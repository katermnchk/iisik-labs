12. С demo-employee выполнить examples/lab4/10-completeBooking.graphql для подтверждённой исторической брони 606. Получить COMPLETED; тот же ожидаемый version=1 повторно даёт CONFLICT. Для отдельного Payment Service показать createPayment по брони 607 с demo-client2 без ручных изменений БД.

## Вопросы и ответы

**Чем Mutation отличается от Query?** Query получает данные; Mutation запускает действие, меняющее состояние. Здесь не setStatus для любого объекта, а бронирование, отмена, публикация и начало оплаты со своими правилами.

**Где находятся бизнес-правила?** В TourBusiness, BookingBusiness, PaymentBusiness, UserBusiness. Resolver принимает input и делегирует командному интерфейсу. Один бизнес-сервис работает с разными хранилищами через Store.

**Зачем business-core?** Чтобы проверки не расходились между изменяемыми заглушками GraphQL и внутренними сервисами с PostgreSQL. В этом модуле нет БД и сетевого транспорта. В каждом приложении создаются только нужные экземпляры и свои заглушки зависимостей.

**Почему GraphQL не меняет PostgreSQL?** По условию взаимодействие пока изолировано. Он выполняет те же команды над локальным изменяемым состоянием. Внутренние сервисы отдельно проверяют сохранение в своей БД.

**Что будет при повторе createBooking?** Пользователь, операция и ключ образуют scope. Если fingerprint совпал — возвращается объект с прежним id. Если payload изменился — CONFLICT. В БД квитанция сохраняется в той же транзакции.

**Как защищены последние места?** В memory-командах есть общий монитор, в persistent-командах — транзакция и pg_advisory_xact_lock в своей БД. Места проверяются и меняются под блокировкой. Для небольшого учебного объёма блокируется весь поток команд одной БД; для большой нагрузки нужна более узкая блокировка агрегата.

**Зачем expectedVersion и expectedPriceVersion?** Первый защищает редактирование объекта от потерянных обновлений. Второй заставляет клиента согласиться с актуальной ценой перед бронированием.

**Почему цена хранится в копейках?** long сохраняет денежную сумму без погрешности double. Итог вычисляется Math.multiplyExact; переполнение обрабатывается с освобождением резерва.

**Зачем снимки в Booking?** Название, цена и дата сохраняют условия бронирования, даже если каталог позднее поменяется.

**Какие переходы статусов есть?** Новый тур DRAFT → PUBLISHED при наличии OPEN выезда. Новая бронь PENDING_PAYMENT → CANCELLED без активной оплаты. CONFIRMED → COMPLETED выполняет сотрудник после начала поездки. Произвольно подтверждать оплату через смену статуса нельзя.

**Что означает PENDING в Payment?** Создана попытка оплаты. Факт получения денег не подтверждён. Провайдер, callback, возвраты и события будут добавлены в следующих работах.

**Почему дробное количество не принимается REST?** travelerCount — целое число туристов. JSON 1.9 должен дать 400, а не превратиться в 1. Обязательная цена также не должна исчезать и превращаться в 0; бесплатный выезд допускается только с явно указанной нулевой ценой.

**Что произойдёт при переполнении сводки?** Возвращается AMOUNT_OVERFLOW. Значение не обрезается и не превращается в отрицательную сумму.

**Почему смена offset не считается переносом?** 05:00Z и 08:00+03:00 обозначают один момент. isEqual сравнивает момент, equals дополнительно сравнивает представление offset.

**Что считается агрегацией?** count и суммы по набору броней, количества по статусам; ранее были продажи, возвраты и загрузка. bookingSummary считает текущий отфильтрованный набор, а salesAnalytics — отдельную подготовленную проекцию.

**Почему важен totalCount до страницы?** Число показывает все совпадения фильтра. items содержит только выбранную страницу. Сортировка применяется до разбиения, при равных значениях порядок определяет id.

**Как обрабатываются ошибки?** NOT_FOUND, FORBIDDEN, BAD_REQUEST, CONFLICT, PRICE_CHANGED, INSUFFICIENT_SEATS, INVALID_STATE. В GraphQL ошибки выполнения идут в errors при HTTP 200; диагностический REST использует 400/401/403/404/409. Внутренние детали БД клиенту не возвращаются.

**Что дополнительно исследовано?** Конкурентные заявки на последний запас мест и чтение одновременно с заменой объекта в memory-хранилище. Важен не порядок потоков, а отсутствие превышения вместимости и пропадания существующих данных.

**Что сохраняется после рестарта?** Внутренние БД, квитанции повторов и локальный Tour stub Booking Service. Gateway специально хранит данные только до перезапуска.
