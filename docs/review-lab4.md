# Независимое ревью ЛР4 и исправления

Ревью кода и отчёта выполнено отдельно от первичной реализации. Оценка не подменяет шкалу преподавателя: ниже перечислены проверяемые замечания и доказательства исправления.

| Замечание | Исправление | Проверка |
|---|---|---|
| На чистых данных внутреннего Payment не было успешного начала оплаты | Добавлена согласованная бронь 607 второго клиента без активного платежа; прямой SQL UPDATE из сценария проверки удалён | Реальные create/read/retry/restart Payment |
| Завершение брони нельзя было успешно показать при фиксированном времени | Исторический выезд 307, подтверждённая оплаченная бронь 606, платёж 708 и факт продажи до проверяемого октябрьского периода | Успешные GraphQL/REST COMPLETED + история |
| Пропущенная или null цена REST превращалась в 0 | Обязательное nullable-поле с проверкой конструктора; положительные обязательные версии | StrictRequestJsonTest + HTTP 400 |
| REST дробные числа усекались до целых | Отключено ACCEPT_FLOAT_AS_INT, включена строгая проверка null/unknown fields; patch-поля остаются необязательными | 7 тестов JSON-контрактов + HTTP |
| Сводка больших валидных сумм давала INTERNAL_ERROR | ArithmeticException преобразуется в AMOUNT_OVERFLOW | summaryOverflowIsReportedAsDomainError |
| Одинаковый instant с другим offset считался переносом | OffsetDateTime.isEqual | equalInstantsWithDifferentOffsetsAreNotScheduleMoves + REST |
| Postman требовал ручного выбора порядка и отдельной брони для оплаты | Коллекция разделена на последовательные папки; отдельная платёжная бронь; id/версии передаются скриптами | PostmanFlowTest выполняет все 12 запросов |
| Схема неточно показывала Query через командные интерфейсы | На рисунке показан именно путь Mutation | Проверка текста и рендера отчёта |
| Срок удержания мог восприниматься как автоматическое освобождение | Уточнены фиксированные часы, проверка оплаты и отсутствие таймера | Сверка с кодом, без добавления несогласованных функций |
| В описании эксперимента говорилось о разных клиентах | Указаны 20 конкурентных запросов клиента | Сверка Principal в тесте |
| В отчёте был только ответ Mutation | Добавлен полный запрос createBooking и указание второго терминала | Воспроизведение и визуальная проверка |

Все воспроизводимые ошибки сначала подтверждены падающими проверками, затем исправлены. Итоговые количества тестов и интеграционных сценариев находятся в актуальных maven-verify.log и integration-summary.json; старые числа не являются результатом этой проверки.

Не подтверждённые при повторной проверке подозрения о наложении текста на футер и неправильном JSON-экранировании сняты: измерение координат PDF не показало пересечения; коллекция разобрана JSON/GraphQL-парсерами и выполнена отдельным тестом.

Границы методички сохранены: только локальные заглушки, отдельные БД, никакого реального межсервисного HTTP/gRPC/Kafka. Оплата только инициируется. Docker Compose не проверялся в контейнерном запуске.
